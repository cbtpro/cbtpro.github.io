看起来眼睛痛，但其实关键的信息就两句

- `allocation failure scavenge might not succeed`（分配失败，清除程序可能不会成功）
- `FATAL ERROR: Ineffective mark-compacts near heap limit Allocation failed - JavaScript heap out of memory`（致命错误：无效的标记压缩接近堆限制分配失败 - JavaScript 堆内存不足）
增加node的`max_old_space_size`即可，“旧空间”是 V8 托管（也称为垃圾收集）堆（即 JavaScript 对象所在的位置）中最大和最可配置的部分，并且 `--max-old-space-size` 标志控制其最大大小。随着内存消耗接近极限，V8 将花费更多时间在垃圾收集上，以释放未使用的内存。

加多少合适呢，可以参考下面的文档。

参考文档：

[nodejs.cn/api/cli.htm…](https://nodejs.cn/api/cli.html#--max-old-space-sizesize%E4%BB%A5%E5%85%86%E5%AD%97%E8%8A%82%E4%B8%BA%E5%8D%95%E4%BD%8D)

[stackoverflow.com/questions/4…](https://stackoverflow.com/questions/48387040/how-do-i-determine-the-correct-max-old-space-size-for-node-js/63495296#63495296)

没加内存前的默认配置

![Node.js 默认内存配置](/assets/images/2024/03/12/node-default.webp)

tip：退出使用`.exit`

widnow可以打开一个cmd或shell，一般你用什么终端启动项目，就在哪个终端里执行下面的命令，如果使用gitbash，则需要用下面的linux/unix的命令。
我的电脑内存比较富裕，直接给最大10g，但实际上给大一些，内存也没有满过，V8的GC（内存垃圾回收）还是很强的。

```shell
setx NODE_OPTIONS --max_old_space_size=10240
```

![setx 设置 NODE_OPTIONS](/assets/images/2024/03/12/node-setx-result.webp)

![环境变量设置结果](/assets/images/2024/03/12/node-system-env.webp)

按照上面的方法设置后，不仅项目启动速度变快了，热更新时再也没有因为垃圾回收内存不够造成项目中断的情况了，问题解决。
设置也可以手动去设置
![手动设置环境变量](/assets/images/2024/03/12/node-env-dialog.webp)

每次打开cmd和powershell启动项目时都会生效。

如果想在window下的git_bash中永久生效，则则需要再用户主目录下的.bash_profile（不能存在就需要创建，建议UTF-8字符集）里配置，重新打开git_bash就可以生效了。

```shell
export NODE_OPTIONS="--max_old_space_size=10240"
```

![.bash_profile 配置](/assets/images/2024/03/12/node-bash-profile.webp)

扩展

linux/unix可以打开一个zsh、shell里执行

```shell
export NODE_OPTIONS="--max_old_space_size=10240"
```

但这只是临时的，关闭shell后，就会失效，如果想要长期生效，可以将这句命令添加到`~/.profile`、`~/.zshrc`,具体加到哪里，看你使用的终端类型。

当然也可以直接使用node

```shell
$ node --max-old-space-size=8192 index.js
```

也可以在当前项目中设置

```json
{
  "scripts": {
    "dev:test": "node --max-old-space-size=8192 其他命令"
  }
}
```

可以使用cross-env来抹平系统差异

```json
{
  "scripts": {
    "dev:test": "cross-env NODE_OPTIONS=--max-old-space-size=8192 其他命令"
  }
}
```

如果觉得上面的方法比较繁琐，也可以使用下面的方法.

## increase-memory-limit

1. 安装并增加内存限制：
首先，运行以下命令安装内存限制工具：

```bash
npm install -g increase-memory-limit
```

然后，执行增加内存限制的命令：

```bash
increase-memory-limit
```
2. 尝试运行项目：
尝试运行项目时，有一部分电脑可能可以直接执行成功，但也有可能再次报错：

```bash
“node --max-old-space-size=10240“ 不是内部或外部命令，也不是可运行的程序
```
3. 解决报错问题：
如果遇到上述报错，可以通过以下步骤解决：

替换 `./node_modules/.bin` 下 `.bat` 文件夹中的 `"%_prog%"`，将其替换成 `%_prog%`（去掉双引号）。
4. 打开 VS Code 设置，找到 Search: Exclude 选项。
5. 删除 `**/node_modules` 项。
6. 再次运行项目：
现在，尝试重新运行项目，应该可以正常运行了。
解决后记得将删除的`**/node_modules`添加回去，提高vscode的性能。
